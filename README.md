# Nielsen-and-Semita-Riemann-Proof-in-Lean4
Proof of the Riemann Hypothesis in Lean4

The paper is [`RH Final Nielsen semita.pdf`](RH%20Final%20Nielsen%20semita.pdf); the Lean formalization is in [`RH/`](RH/).

## Building locally

### 1. Install Lean (via elan)

[elan](https://github.com/leanprover/elan) is the Lean version manager. It reads `lean-toolchain` and installs the exact Lean version this project needs (`v4.16.0-rc1`) automatically, so you don't install Lean itself by hand.

**Linux / macOS / WSL:**
```bash
curl -sSf https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh
source ~/.elan/env   # or open a new terminal
```

**Windows (PowerShell):**
```powershell
curl.exe -O --location https://raw.githubusercontent.com/leanprover/elan/master/elan-init.ps1
powershell -ExecutionPolicy Bypass -f elan-init.ps1
del elan-init.ps1
```

You also need `git`.

### 2. Clone and build

```bash
git clone https://github.com/startigerjln/Nielsen-and-Semita-Riemann-Proof-in-Lean4
cd Nielsen-and-Semita-Riemann-Proof-in-Lean4
lake exe cache get
lake build
```

- `lake exe cache get` downloads Mathlib and its prebuilt files (~5,800 files, a few GB on disk). **Don't skip it.** Without it, `lake build` compiles all of Mathlib from source, which takes an hour or more.
- `lake build` then compiles the project itself in a minute or two. A successful build ends with:
  ```
  ✔ [801/802] Built RH
  Build completed successfully.
  ```
  Warnings about missing doc-strings come from Mathlib and can be ignored.

### 3. Inspecting the result (optional)

To see exactly which axioms the main theorem depends on, create a scratch file (e.g. `Check.lean`, don't commit it) in the repo root:

```lean
import RH
#print axioms riemann_hypothesis_resolved
```

and run:

```bash
lake env lean Check.lean
```

### Editing in VS Code

Install the [Lean 4 extension](https://marketplace.visualstudio.com/items?itemName=leanprover.lean4), then open the repository **folder** (not an individual file) so the extension picks up the project settings. Run `lake exe cache get` first, or the editor will try to compile Mathlib.

## Project layout

| Path | Contents |
|---|---|
| `RH.lean` | Root module; imports everything |
| `RH/*.lean` | Formalization (`Defs`, `Soundness`, `Obstruction`, `Independence`, `TruthInN`, `ProofII`, `ProofIII`, `Main`) |

| `lake-manifest.json` | Exact dependency versions (generated by Lake; commit it) |

## Troubleshooting

- **`lake exe cache get` reports "0% success" / "No cache files to decompress":** `lean-toolchain` doesn't match the Lean version the pinned Mathlib commit was built with. Restore `lean-toolchain` to `leanprover/lean4:v4.16.0-rc1`.
- **Don't run `lake update`** unless you mean to upgrade Mathlib. It moves Mathlib to the latest version, which will likely break the build and require updating `lean-toolchain` to match.
- **`no such file or directory ... RH/RH/Main.lean`:** `lakefile.lean` has a `srcDir := "RH"` line; remove it. Modules are named `RH.*`, so the source root is the repo root.
- **Something is stale or corrupted:** delete `.lake/build` and run `lake build` again. (Deleting all of `.lake` also works, but then you need `lake exe cache get` again.)
